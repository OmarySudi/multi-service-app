# Multi-Service Spring Boot Application

A multi-module Spring Boot application with JWT authentication and protected dashboard APIs.

## Architecture

This project follows a multi-module architecture with the following modules:

- **common**: Shared utilities, DTOs, and opt-in security library
- **repository**: Shared repository interfaces and data access patterns
- **services/authentication-service**: JWT-based authentication service with role management
- **services/dashboard-service**: Dashboard APIs with permission-based access control

## Tech Stack

- Java 17
- Spring Boot 3.2.0
- Spring Security
- JWT (JSON Web Tokens)
- Lombok
- Gradle

## Getting Started

### Prerequisites

- JDK 17 or higher
- Gradle 8.x

### Build the Project

```bash
./gradlew clean build
```

### Run Authentication Service

```bash
./gradlew :services:authentication-service:bootRun
```

The authentication service will start on `http://localhost:8081`

### Run Dashboard Service

```bash
./gradlew :services:dashboard-service:bootRun
```

The dashboard service will start on `http://localhost:8082`

## API Endpoints

### Authentication Service (Port 8081)

- `POST /api/auth/register` - Register new user
- `POST /api/auth/login` - Login and get JWT token
- `GET /api/auth/validate` - Validate JWT token

### Dashboard Service (Port 8082)

- `GET /api/dashboard/stats` - Get dashboard statistics (Protected)
- `GET /api/dashboard/profile` - Get user profile (Protected)

## Authentication Flow

1. Register or login via authentication service to get JWT token
2. Include the JWT token in the Authorization header for dashboard service requests:
   ```
   Authorization: Bearer <your-jwt-token>
   ```

## Configuration

Each service has its own `application.yml` file for configuration:

- **authentication-service**: Port 8081, JWT secret, token expiration
- **dashboard-service**: Port 8082, JWT secret (must match authentication-service)

**Important**: Both services must use the same JWT secret for token generation and validation to work correctly.

## Development Notes

- **Opt-In Security**: Security is NOT enabled by default - must set `jwt.security.enabled=true`
- **Flexible Common Module**: Services can use JwtUtil and DTOs without being forced into security
- **Permission-Based Access**: Use `@PreAuthorize` annotations for role-based access control
- **Role Management**: JWT tokens include user roles for fine-grained authorization
- JWT tokens are generated by the authentication service with roles
- Token validation happens via the shared JwtAuthenticationFilter (when enabled)
- All passwords are encrypted using BCrypt (auto-configured)
- No inter-service API calls are required for token validation

### How It Works

#### For Protected Services (like Dashboard):
1. Include `common` module in dependencies
2. Add `jwt.security.enabled=true` to `application.yml`
3. Add JWT secret to `application.yml`
4. Use `@PreAuthorize` on endpoints for permission control
5. Security auto-configures with JWT authentication

#### For Services Not Needing Security (like Integrations):
1. Include `common` module in dependencies
2. Don't set `jwt.security.enabled`
3. Use JwtUtil for making authenticated calls to other services
4. No security filters are loaded
